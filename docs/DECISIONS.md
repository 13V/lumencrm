# Decisions

- This is a repository application for Supabase and Vercel, as requested; it is not hosted through Sites.
- No existing client records were present. Development preview data is explicitly fictional and isolated from Supabase. Production cannot enable preview mode.
- Staff can read the operational price list and selected working-hour settings through an allowlisted function, while bank details and the full settings row remain owner-only.
- Owner TOTP is enforced by both the application and database policies. Membership is provisioned explicitly; a stranger cannot become owner by signing in first.
- Some supplied dark-mode muted colours do not meet normal-text AA on all supplied surfaces. Muted text is lightened while keeping the requested neutral palette.
- Auth pages, manifest and service-worker assets necessarily remain reachable before login; CRM data routes require authentication. Capability URLs and signed integration routes have their separate access checks.
- A PostgreSQL database is required for live transaction and RLS checks. Unit and preview-browser tests are not represented as proof of live database behaviour.

- Idempotency uses the exact canonical identities in the brief, but hashes those identities before storing them in integration receipts because a Chloe identity includes a phone number. Personal payloads live only in the business tables.
- Ingestion completes its short identity/deduplication transaction before responding so the returned deal ID is durable. Notifications run after the response and are also queued for recovery. A live latency check is required; local unit timing is not a network SLA.
- Website forwarding requires a nonempty `event_id`, in addition to the named contact and phone/email, because durable idempotency cannot be guaranteed without it. Missing IDs receive a field-level 400 response; the sender should retain its existing website event ID across retries.
- Sending a message requires recorded enquiry-related or explicit consent. SMS includes a STOP footer; email identifies the business and supports reply-unsubscribe. The owner must monitor email replies and record opt-outs until email-inbound forwarding is connected.
- Private calendar tokens are generated from 32 random bytes, shown once and stored only as hashes. Revoking a feed invalidates its URL immediately.
- Common business, billing, call-hour and message-template settings have dedicated forms. Rare configuration, including project templates and custom stage arrays, remains in a validated advanced editor. Canonical stage keys are retained for integrations; labels, order and additional custom stages are editable.

- Quote issue snapshots the product inclusions, business contact details, tax wording, deposit schedule and written terms. Later price-list changes cannot rewrite a sent agreement. Written terms must be configured before issue; the CRM cannot invent an acceptance contract.
- Public quotes use anonymous capability RPCs with internal rate limits and no anonymous table access. The service-role key is not needed to render or accept a quote.
- Full quoted prices remain full prices if GST is enabled later; invoice GST is extracted from the full total rather than added unexpectedly. Bank details are read from owner-only settings when the owner generates an invoice; viewer PDFs omit bank details.
- Invoice PDFs use a static instance of the licensed Inter font. Variable-font subsetting failed in the PDF library, so the same local font was converted to a regular TTF for reliable Unicode rendering.

- Cohort funnel percentages use the full enquiry cohort as denominator. Moving directly to a later stage does not fabricate intermediate milestones. Every rate shows its sample size.
- Source/trade filters narrow outcomes while retaining an ad's actual matched spend; reports label this explicitly. Current client portfolio metrics are independent of enquiry filters. Churn shows cancellation counts rather than inventing a rate without historical subscription-status snapshots.
- Quote history imported from CSV cannot invent a sent agreement. Import such a lead at Demo sent, attach its actual quote, then move it forward. Historical Won imports require a recorded override reason. Date-only CSV values are interpreted as 9am Adelaide time and shown in the dry run.
- CSV uploads are limited to 1,000 rows and 2 MB per batch. Exports fail visibly above 10,000 rows per table or 50 MB and support date-range filtering; they never silently truncate. Larger downloads use temporary private Storage links because Vercel functions limit request/response bodies to 4.5 MB. Files up to 25 MB upload directly to signed Supabase Storage URLs and are confirmed before display.
- Offline mode caches the last authorised operational snapshot on that device, with a read-only interface and no queued writes. It excludes settings, financial documents and public quotes; signing out clears the snapshot. It does not provide offline authentication to a new device.
- Reversible stage, contact, task and checklist changes save through explicit actions or direct controls. Notes preserve an unsent local draft. Sends, quote acceptance, imports and anonymisation remain deliberate actions; an external message or a signed acceptance cannot truthfully be undone. The 30-day bin applies to ordinary deletion, not irreversible anonymisation.
- The optional AI helper uses Anthropic's Messages API, off by default. A click sends only selected lead context or pasted text and the current price list. Output remains an editable draft. Provider/model are documented and configurable; no tool use or automatic client sending is allowed.
- Weekly encrypted exports are supplementary logical backups, with a 35-day retention period. They do not include Auth credentials or Storage binaries and are not transaction-consistent database snapshots. Supabase backups and a documented restore drill remain required.
- Retention defaults to **12 months**, following Troy's clarification and the current [Lumen privacy policy](https://www.lumenadl.com/privacy.html), checked 4 November 2026. This replaces the original brief's 24-month default. The setting remains editable; open enquiries and customers are protected from automatic lost/no-reply anonymisation. The website was not changed.
- Performance checks use an isolated production-optimised copy with fictional data and local quote RPC fixtures. The release source continues to forbid demo mode in production. These checks measure UI assets and interaction, not hosted authentication, database latency or provider delivery.
- The first-load JavaScript target is not yet met: the measured fixture transfers 337,950 bytes of scripts despite lazy secondary panels. Lighthouse met the 90+ target. Further bundle reduction is separate from claiming a smaller measured payload.
- Bulk selection currently offers Snooze. Calendar is an agenda with booking and a private feed, without drag rescheduling. Contact/business and financial forms use explicit Save; financial operations do not have a general Undo contract. Ordinary reversible CRM actions and bulk snooze do. These are current interface limits, not claims of universal autosave/Undo.
- Mutations use authenticated, same-origin JSON route handlers and transactional database functions rather than Next.js Server Actions. Server Components perform the initial authorised reads. This keeps the role/validation boundary explicit and shares the integration-friendly error shape across phone actions.
